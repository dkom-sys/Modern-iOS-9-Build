# Project Update — Day 1
## Initial Research & Project Direction

Today marked the beginning of the project to modernize the first-generation iPad mini.

The goal is simple:

> **Make iOS 9 breathe again.**

Rather than trying to replace the hardware or force a modern version of iOS onto an architecture it was never designed for, the current plan is to work with the existing platform and modernize the software around it.

---

## Hardware

The target device has been identified as:

- **Model:** iPad2,5
- **Board:** p105ap
- **SoC:** Apple A5
- **Platform:** s5l8942x
- **RAM:** 512 MB
- **Architecture:** ARMv7 / 32-bit

### RAM Upgrade

Initially, a RAM upgrade to 2 GB was considered.

After examining how the A5 platform is constructed, this was determined to be a significantly more complicated problem than simply replacing a memory chip.

The RAM is integrated into the A5 package using package-on-package (PoP) construction.

A higher-capacity configuration would require investigation into:

- A5 memory-controller capabilities
- Supported LPDDR2 configurations
- Memory addressing
- Package compatibility
- Bootloader initialization
- Operating-system memory detection
- Power requirements

For now, the RAM upgrade has been **removed from the primary project scope**.

The original **512 MB configuration will remain.**

This limitation will instead become a design constraint for the modernized operating system.

---

## CPU Upgrade

A CPU/SoC upgrade was also considered.

A simple A5 replacement may theoretically be possible depending on the exact package and revision, but moving to a fundamentally different SoC would involve much more than replacing the processor.

A different SoC could require changes to:

- Memory configuration
- Power management
- Board routing
- Boot ROM expectations
- Bootloader configuration
- Drivers
- GPU support
- Peripheral interfaces
- Hardware identification

Therefore, CPU upgrades are currently **outside the project's main scope**.

Hardware experimentation may be revisited later using sacrificial donor boards.

---

# Donor Hardware

An important decision was made today:

> **The original iPad will not be used for destructive experimentation.**

The current iPad will remain the project's **known-good reference device**.

Future hardware research will be performed using dead or donor iPad mini boards.

Potential research areas include:

- A5 package analysis
- RAM configuration
- NAND/storage
- Power management
- Board-level hardware
- Possible hardware modifications

The intention is to understand the platform without risking the original device.

---

# IPSW Research

The original iOS 9.3.5 IPSW has already been extracted and examined.

### Firmware

The IPSW contains:

- `BuildManifest.plist`
- `Restore.plist`
- `kernelcache.release.p105`
- Multiple DMG images
- Boot firmware
- DFU components
- DeviceTree
- iBoot
- LLB
- iBSS
- iBEC
- Other firmware resources

The board configuration and platform information have been identified from the firmware metadata.

---

# IMG3 Research

The boot components use Apple's **IMG3** container format.

Initial inspection identified several IMG3 structures, including:

- `DATA`
- `VERS`
- `SEPO`
- `CHIP`
- `BORD`
- `KBAG`

The `CHIP` information corresponds to the **0x8942** platform.

The boot components are therefore not simply raw executable files that can be immediately loaded into a disassembler.

Further research into the IMG3 structure, encryption, payload extraction, and signing is required.

# Current Software Goal

The project direction has now been narrowed considerably.

Rather than attempting to create a completely new operating system, the plan is to investigate how much of iOS 9.3.5 can be:

- Debloated
- Optimized
- Reconfigured
- Replaced
- Modernized
- Extended

while retaining compatibility with the original A5 platform.

Potential future targets include:

- SpringBoard
- System services
- Frameworks
- WebKit
- Applications
- Background daemons
- UI components
- System utilities

The first priority is **understanding the existing system before modifying it.**

---

# Development Philosophy

The project will follow several principles:

### 1. Preserve the original

The original IPSW will remain untouched.

All experimentation will use working copies.

### 2. Don't destroy the reference device

The original iPad remains the known-good reference.

### 3. Understand before modifying

No blind firmware modifications.

Every component should be investigated before attempting to change it.

### 4. Design around 512 MB

The goal is not to hide the hardware limitations.

The goal is to build software that works **with** them.

### 5. Document everything

Experiments, failures, discoveries, firmware structures, and observations will be documented in this repository.
